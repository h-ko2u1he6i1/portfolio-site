概要

Works（制作実績）と Study（個人開発）は、同じ手順で追加できます。やることは大きく 2 つだけです。

  1. 作品の画像を用意して、決まったフォルダに置く
  2. データファイルに 1 ブロック追記する

あとは変更を GitHub の main ブランチに送れば、Vercel が自動でビルドし、数分後に本番サイトへ反映されます。

用意するもの

もの説明
プロジェクト一式portfolio-site フォルダ（GitHub からクローン／ダウンロード済みのもの）
テキストエディタVS Code 推奨（無料）。メモ帳でも可
作品の画像次の手順のサイズで書き出したもの
Node.js（任意）ローカルで見た目を確認したい場合のみ。無くても追加はできる
1

画像を準備する

必須 — サムネイル画像（image）。一覧のカードと詳細ページの大きい画像に使われます。

項目推奨
縦横比3 : 2（横長）※カードは中央を自動トリミング
サイズ横 1500px 前後（例 1500 × 1000px）
形式JPEG（写真系）または PNG
容量500KB 以下が目安

任意 — 詳細ページ用のスクリーンショット。詳細ページ下部に「プレビュー」枠として表示できます。

種類用途推奨サイズ
PC 版フルスクショページ全体を上から下まで撮ったもの横 1440–1600px（縦は長くて可）
スマホ版フルスクショスマホ表示のページ全体横 600–750px（縦は長くて可）

任意 — 紹介動画。.mp4 形式。1080p 以下・数 MB に圧縮しておくこと。PC 用・スマホ用を分けられます。

ファイル名は半角英数字とハイフンのみ。既存の命名に合わせると分かりやすいです（番号は「今ある最大番号 + 1」が安全）。

ファイル名の例
サムネイル          … works-img17.jpg
PC フルスクショ     … worksdetail-img17.jpg
スマホフルスクショ  … worksdetail-img17.sp.jpg
動画（PC）          … worksdetail-movie17.mp4
動画（スマホ）      … worksdetail-movie17.sp.mp4
2

フォルダに置く

  • 画像 → portfolio-site/public/img/ の中
  • 動画 → portfolio-site/public/videos/ の中

にコピーするだけです。

パスの書き方 データファイルでは先頭に / を付けて書きます。
public/img/works-img17.jpg → データ上は "/img/works-img17.jpg"
3

データファイルに追記する

開くファイルは追加する種類によって異なります。

  • Works（制作実績）→ portfolio-site/src/data/works.ts
  • Study（個人開発）→ portfolio-site/src/data/studies.ts

中身は次のような構造です。配列（[ ... ]）の中に、作品ごとの { ... } ブロックが並んでいます。

src/data/works.ts（一部）
export const worksData: Work[] = [
  {
    id: 1,
    slug: '1',
    title: "一般財団法人 建設業振興基金",
    longDescription: "コーポレートサイトの…",
    image: "/img/works-img01.jpg",
    role: "Coding / WordPress",
    externalLink: "https://www.kensetsu-kikin.or.jp/",
  },
  { /* …次の作品… */ },
];   ← この ]; の手前に新しいブロックを足す

雛形をコピーして貼り付けます。一覧の先頭に出したいなら [ のすぐ下に、末尾に出したいなら最後の }, と ]; の間に貼ります。

貼り付ける雛形
  {
    id: 17,
    slug: "17",
    title: "ここに作品名",
    longDescription:
      "ここに説明文。改行は \n を入れる。\n\n空行も作れます。",
    image: "/img/works-img17.jpg",
    role: "Coding",
    externalLink: "https://example.com/",
  },
よくあるミス 貼り付けたら、前のブロックの末尾に ,（カンマ）があるか必ず確認してください。{ … } と { … } の間はカンマで区切ります。クォート " の閉じ忘れも要注意です。

各項目の書き方

項目必須書き方・注意
id必須他とかぶらない数字。普通は「今ある最大 + 1」。画面には出ません。
slug必須URL の末尾になる文字列。他とかぶらない。半角英数字とハイフンのみ（例 "17"、"rohto-lp"）。
title必須作品名。一覧・詳細・ブラウザのタブに出ます。
longDescription必須詳細ページの本文。改行は \n（バックスラッシュ + n）。冒頭 120 文字が検索結果の説明文に使われます。
image必須手順 2 で置いた画像のパス。/img/ から始める。
role必須肩書き。フィルターに載せるには "Design" か "Coding" を含める。例 "Coding / WordPress"、"Design"。
externalLink任意公開サイトの URL。必ず https:// から。無いならこの行ごと削除する。
detailImage任意PC 版フルスクショのパス。例 "/img/worksdetail-img17.jpg"
detailImageSp任意スマホ版フルスクショのパス。例 "/img/worksdetail-img17.sp.jpg"
movie任意PC 用動画のパス。例 "/videos/worksdetail-movie17.mp4"
movieSp任意スマホ用動画のパス。例 "/videos/worksdetail-movie17.sp.mp4"

任意の項目は「使うときだけ書く」。使わない項目は行ごと消してください（空文字 "" を残さない）。

プレビュー枠の条件 detailImage / detailImageSp / movie / movieSp のいずれか 1 つでもあると、詳細ページに「プレビュー」セクションが表示されます（順に PC 画像 → スマホ画像 → PC 動画 → スマホ動画）。

例 — フルスクショ付きのデザイン案件

src/data/works.ts に追記
  {
    id: 18,
    slug: "18",
    title: "〇〇株式会社 採用サイト",
    longDescription:
      "採用サイトのデザインを担当しました。信頼感を伝えるため青を基調に…",
    image: "/img/works-img18.jpg",
    role: "Design",
    externalLink: "https://recruit.example.co.jp/",
    detailImage: "/img/worksdetail-img18.jpg",
    detailImageSp: "/img/worksdetail-img18.sp.jpg",
  },

src/data/studies.ts に追記

4

ローカルで確認する（任意・推奨）

Node.js が入っていれば、アップ前に手元で見た目を確認できます。

ターミナル
cd portfolio-site
npm install     # 初回のみ
npm run dev

ブラウザで http://localhost:3000/works を開いて、次を確認します。

  • 一覧に新しいカードが出ている
  • カードをクリックすると詳細ページが開く
  • 画像が表示される（真っ白／グレーなら画像パスかファイル名ミス）
  • 説明文の改行が意図どおり

止めるときはターミナルで Ctrl + C。

赤いエラー画面が出たら たいていはカンマの付け忘れかクォート " の閉じ忘れです。手順 3 の注意書きを見直してください。
5

GitHub にアップする（本番反映）

main ブランチに変更を送ると、Vercel が自動でビルドして数分で本番に反映されます。

方法 A — コマンドで送る

ターミナル
cd portfolio-site
git checkout -b add-work-17          # 作業用ブランチ
git add public/img/works-img17.jpg src/data/works.ts
git commit -m "作品追加: 〇〇株式会社 採用サイト"
git push -u origin add-work-17

その後 GitHub 上で Pull Request を作成し「Merge」。main に入った時点で本番反映が始まります。直接 main に push できる運用なら、1 行目の git checkout -b を飛ばして main のまま add → commit → push で OK です。

方法 B — GitHub のサイト上で編集する

  1. GitHub でリポジトリを開く。
  2. public/img/ に入り「Add file」→「Upload files」で画像をアップ。
  3. src/data/works.ts を開き、鉛筆アイコン（Edit）で手順 3 の追記をする。
  4. ページ下部「Commit changes」で保存（main に直接、またはブランチ + PR）。

反映の確認

  • Vercel のダッシュボードで最新デプロイが Ready になったら完了。
  • 本番サイトの /works（または /studies）を再読み込みして確認。
  • 本番が Basic 認証つきの場合は、設定済みの ID / パスワードが必要です。

困ったとき

症状原因と対処
ビルド／npm run dev が赤いエラーカンマ抜け・クォート閉じ忘れ・波カッコ {} の対応ミス。追記部分を見直す。
カードは出るが画像がグレー／出ないimage のパス綴り間違い、または画像を public/img/ に置き忘れ。大文字小文字も区別される。
「サイトを見る」ボタンを出したいのに出ないexternalLink が無い、または https:// が抜けている。
詳細ページに「プレビュー」枠が出ないdetailImage / detailImageSp / movie / movieSp が 1 つも無いと枠自体が出ない仕様（正常）。
新しい作品ページが 404本番はビルド時にページを作るため、デプロイ完了前は 404。Vercel が Ready になるまで待つ。slug の重複でも起きる。
トップページに出ないトップは各カテゴリ先頭 4 件のみ表示。5 番目以降は /works・/studies の一覧のみ。
並び順を変えたいworks.ts / studies.ts の配列の並び順がそのまま表示順。ブロックごと上下に移動する。id の数字は順不同で OK。

1全体像

フレームワークNext.js 16.1.6（App Router / Turbopack）
言語TypeScript 5、React 19.1.0
スタイルグローバル CSS（globals.css）＋ CSS Modules。CSS 変数でトークン管理
アニメーションCSS 主体のリビール ＋ motion（Framer Motion）＋ WebGL（three.js / R3F）ヒーロー背景
データTS ファイルにベタ書き（src/data/*.ts）。CMS・DB なし
認証Basic 認証（src/proxy.ts、環境変数で ON/OFF）
ホスティングVercel。画像は next/image で最適化、動画は public/videos/ を直配信

設計思想

  • コンテンツはコード。作品追加はデータ配列に 1 要素足すだけで、一覧・詳細・sitemap すべてに反映される。
  • JS が無くても本文は見える。リビール演出は <html> に .js が付いたときだけ有効化する。
  • 1 つのカードコンポーネントを使い回す。Works と Study は同じ型・同じ UI を共有する。

4データモデル

4.1型定義（src/types/portfolio.ts）

src/types/portfolio.ts
export interface PortfolioItem {
  id: number;              // 一意の識別子（React key に使用。画面には出ない）
  slug: string;            // URL の末尾（/works/<slug>）。一意・URL セーフ
  title: string;           // 作品名
  longDescription: string; // 詳細本文。"\n" は改行(<br>)になる
  image: string;           // メイン画像。"/img/xxx.jpg"
  role: string;            // 肩書き。"Design" / "Coding / WordPress" 等
  externalLink?: string;   // 公開 URL（https:// 必須）
  detailImage?: string;    // 詳細ページの縦長フルスクショ（PC）
  detailImageSp?: string;  // 同（スマホ）
  movie?: string;          // 紹介動画 mp4（PC）
  movieSp?: string;        // 同（スマホ）
}

Work と Study はどちらも PortfolioItem の別名。

4.2各フィールドの扱い

フィールド必須使われ方 / 注意
id必須配列内で重複させない。重複すると React の key 警告＋描画不整合。
slug必須/works/<slug> の URL になる。重複禁止。半角英数字とハイフン推奨（現状は連番）。
title必須一覧カード見出し、詳細 <h1>、<title>、OGP。
longDescription必須詳細本文。\n で改行。冒頭 120 文字が meta description / OGP に自動転用。
image必須一覧カード（3:2 で中央トリミング）、詳細カバー（原寸・約 12% 拡大）、動画ポスター、OGP 画像。/img/ 始まり。ファイルが無いとエラー。
role必須一覧・詳細の Role 行。Works 一覧のフィルターは role に "design" / "coding" が含まれるかで判定（大小文字問わず）。
externalLink任意https:// から始まる絶対 URL のみ（new URL() でパースするため不正だとビルド時エラー）。設定すると Link 行と「サイトを見る」ボタンが出る。
detailImage
detailImageSp		任意詳細下部の「プレビュー」枠。縦長スクショ可（枠内が縦スクロール、最大 78vh）。PC 用 横 1440–1600px、SP 用 横 600–750px 目安。
movie
movieSp		任意public/videos/ の mp4。controls / muted / loop / playsInline / preload="none"、ポスターは image。
プレビュー枠 detailImage / detailImageSp / movie / movieSp のいずれか 1 つでもあると詳細ページに「プレビュー」セクションが表示される（順に PC 画像 → スマホ画像 → PC 動画 → スマホ動画）。

4.3表示順とデータフロー

データの流れ
src/data/works.ts (worksData 配列)
        │
        ├─▶ /            … worksData.slice(0, 4)   配列の先頭 4 件
        ├─▶ /works       … worksData 全件（配列順）＋ role でフィルター
        ├─▶ /works/:slug … worksData.find(slug 一致)
        └─▶ /sitemap.xml … worksData 全件の URL

src/data/studies.ts も同じ構造（フィルター UI は無し）
  • 配列の並び順 = 画面の表示順。先頭に置いた作品ほど上（トップは先頭 4 件のみ）。
  • id は順不同でよい。表示順は配列位置で決まる。

6スタイルシステム

トークン（globals.css の :root）

  • カラー: --paper --paper-dim --surface / --ink --ink-muted --ink-faint / --line --line-strong。

7アニメーション

リビール（CSS 主体）

キモ: コンテンツはデフォルトで見えている。layout.tsx のインライン <script> が <html> に .js を付けた場合のみ、.js .reveal { opacity:0 } が効いて「隠してから出す」状態になる。

動作の流れ
1. サーバーは reveal 要素を通常表示で返す（JS 無し／失敗でも本文が見える）
2. クライアントで <script> が <html>.classList.add('js')
3. useReveal（IntersectionObserver）が可視判定 → is-in を付与 → CSS transition
4. 保険: 1500ms 経っても未発火なら強制 is-in（バックグラウンドタブ対策）
5. prefers-reduced-motion 時は transition を無効化し即表示
  • useReveal<T>() … [ref, inView] を返す。threshold: 0.15、1500ms フォールバック。
  • 1 文字めくり（SplitText / HeroContent）… .char を translateY(115%) rotate(7deg) から none へ。--reveal-delay でスタッガー。
  • Kicker … グラデ棒 scaleX(0→1)、ラベル clip-path の左→右ワイプ。

motion（Framer Motion）を使う箇所

  • WorkCardItem … ホバー variants（画像ズーム／タイトル色／矢印）。
  • WorkDetail … useScroll / useTransform でカバー画像の縦パララックス。
  • HamburgerMenu … AnimatePresence のオーバーレイ、リンクの段階表示。

いずれも useReducedMotion() を尊重。

ヒーロー背景（WebGL）

  • three.js + @react-three/fiber。フルスクリーン矩形＋フラグメントシェーダのみ（3D メッシュなし）。
  • 画面外／prefers-reduced-motion で停止。低負荷設定（dpr 上限 1.1、antialias:false、low-power）。
  • globals.css の .site-content グラデーションで「紙が上にせり上がる」ように境界を溶かしている。

8画像・動画

  • 画像は public/img/、動画は public/videos/。データからは /img/... /videos/... で参照。
  • 画像は原則 next/image 経由（next.config.ts で AVIF / WebP 生成）。Basic 認証のミドルウェア対象から /img/ /videos/ は除外済み。
  • 目安 — サムネイル image: 横 1500px 前後・3:2・JPEG / 詳細 PC スクショ: 横 1440–1600px / SP スクショ: 横 600–750px / 動画: 1080p 以下・数 MB。
  • macOS 例: sips --resampleWidth 1500 input.jpg --out public/img/works-imgXX.jpg
既知の挙動 ローカルで next start すると next/image の最適化が環境依存で失敗し画像が出ないことがあるが、Vercel 上では問題なし。確認は npm run dev か Vercel Preview で。

9Basic 認証（src/proxy.ts）

  • Next 16 では middleware が proxy.ts / export function proxy という名前に変わっている。
  • BASIC_AUTH_USER と BASIC_AUTH_PASSWORD の両方が設定されている時だけ 401 を返す。どちらか空なら素通し（設定漏れで全面ロックしないため）。
  • matcher 除外: api / _next/static / _next/image / favicon.ico / img/ / videos/ / sitemap.xml / robots.txt。

14注意点・ハマりどころ

  • データを足したら再デプロイが必要。詳細ページはビルド時生成のため、main に反映されるまで新 URL は 404。
  • slug / id の重複は不具合のもと。追加時は必ずユニークに。
  • externalLink は https:// を必ず含める。省略時はキー自体を書かない。
  • longDescription の改行は文字列内の \n。通常のダブルクォート文字列なら \n、テンプレートリテラル（バッククォート）なら実改行 OK。
  • 画像・動画のパスは必ず / 始まり（public/ 基準の絶対パス）。./img/... は不可。
  • ~/.git（ホーム直下に誤って作られた空リポジトリ）には触らない。作業対象は portfolio-site/。
